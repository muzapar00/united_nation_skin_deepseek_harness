# Publishing checklist

Everything below happens on GitHub, once, after the first push.

## 1. Repository description and topics

**Description** (Settings → General → Description, keep it under ~350 characters):

> United Nations theme for DeepSeek Harness: white + UN blue, the official emblem, a peacekeeping
> photo rotation, Charter/facts ribbons, and a 7,030-language picker with 127 translated interfaces.
> 联合国主题皮肤：白底联合国蓝、维和背景轮播、宪章与知识丝带、7,030 种语言目录。

**Topics** (Settings → General → Topics):

```
dsh-plugin
deepseek-harness
dsh
theme
skin
united-nations
un
i18n
languages
peacekeeping
```

The `dsh-plugin` topic is how the community directories find plugins — do not skip it.

## 2. Release

The `v0.1.0` tag is already pushed. On GitHub: **Releases → Draft a new release → choose `v0.1.0`**,
title `United Nations skin v0.1.0`, and use the `0.1.0` section of `CHANGELOG.md` as the body.
Attach nothing: the source archives are enough, and the built `client.js` is committed.

## 4. Install path to quote everywhere

```bash
dsh plugin --profile web add github:muzapar00/united_nation_skin_deepseek_harness
# then add "dsh-theme-un" to dsh.profile.bundles in $DSH_HOME/profiles/web/package.json
# or just run the repository installer:
./scripts/install.sh
```

## 5. After each release

1. Update `CHANGELOG.md` and `package.json` / `skin.json` versions together.
2. `node src/build.mjs --check` (this also validates every language pack).
3. Commit `client.js` with the source change; CI rejects a stale bundle.
4. `git tag -a vX.Y.Z -m "..." && git push origin main --tags`.
5. Create the GitHub release from the tag.
